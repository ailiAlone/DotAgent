## Summary

## Project Overview
2D top-down Godot 4 project built around a single main scene with an autoload controller. Architecture is scene-composition + singleton state management: `res://scenes/game.tscn` is the main entry point, owned by `res://scripts/game.gd`, and coordinates the `Player` node and the `HUD` overlay through the global `GameManager` autoload.

## System Modules
| Module | Responsibility | Key Files | Key Functions/Signals |
|--------|---------------|-----------|----------------------|
| **GameManager** | Global game state, score/health tracking, pause control | `res://scripts/game_manager.gd` (autoload) | `add_score()`, `take_damage()`, `toggle_pause()`; signals `score_changed(new_score)`, `health_changed(new_health)`, `game_over()`, `pause_toggled(is_paused)` |
| **Game (main scene)** | Scene composition, signal wiring, game loop entry | `res://scenes/game.tscn`, `res://scripts/game.gd` | `_ready()` (wires GameManager → HUD), `_process()`; owns `$Player` and loads/positions HUD |
| **Player** | Top-down movement and player actions | `res://scripts/player.gd` (node inside `game.tscn`) | `_process(delta)` using `Input.get_vector("move_left", "move_right", "move_up", "move_down")`; movement via `position += direction * SPEED * delta`; `shoot()` if `"shoot"` action is used |
| **HUD** | UI overlay displaying score, health, pause state | `res://scenes/hud.tscn`, `res://scripts/hud.gd` | `update_score(value)`, `update_health(value)`, `_on_score_changed()`, `_on_health_changed()`; targets Label nodes under the root `CanvasLayer` |
| **Input / Project Settings** | Defines mapped actions and autoload order | `res://project.godot` | Input actions: `move_left`, `move_right`, `move_up`, `move_down`, `pause`, `shoot`; autoload `GameManager` |

## Dependencies & Signal Flow
- `project.godot` supplies the `GameManager` autoload and the input action map (`move_*`, `pause`, `shoot`).
- `Game.tscn` is the root scene; it contains the `Player` node and instantiates the `HUD` overlay.
- `Game.gd` in `_ready()` connects `GameManager` state signals to the HUD’s update methods.
- `Player` reads mapped input in `_process()` and updates its own transform; it does not directly own UI but may call `GameManager` methods on gameplay events (e.g., shooting).
- `HUD` subscribes to `GameManager.score_changed` / `health_changed` and updates `CanvasLayer` Label nodes.
- Signal chain example: `Player` action → `GameManager` state change → `score_changed` / `health_changed` emitted → `HUD` label updated.

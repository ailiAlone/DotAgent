### Key Mechanisms & Responsibilities

**Enemy (`Area2D`)**
- Spawns at the top of the screen and moves straight down via `_physics_process`.
- Cleans itself up when it passes below the viewport bottom edge.
- Adds itself to the `"enemies"` group on ready.
- Connects `body_entered` to damage any body in the `"players"` group, then self-destructs.
- Exposes `take_damage(amount)` and `die()` for player/projectile interactions.
- Emits `died(position)` before destruction and awards score through `GameManager.add_score()`.

**Explosion (`Node2D`)**
- Visual-only effect that uses `_draw()` to render an expanding ring.
- lerps radius from `0` to `max_radius` and fades alpha from `1` to `0` over `duration`.
- Calls `queue_free()` once `duration` elapses.

  - `@export var speed: float = 150.0`
  - `@export var health: int = 1`
  - `@export var score_value: int = 100`
- **Methods**
  - `take_damage(amount: int = 1)`

   `enemy.gd` calls `body.take_damage()`. The current `player.gd` has no such method; calling it would crash at runtime.

3. **No bullet system exists in the project.**  
   There is no `bullet.tscn`, `bullet.gd`, shoot input action, or bullet group. The parent task assumes player bullets already exist, but they do not. Integrating enemy-bullet collision will require first creating a bullet scene/script and placing bullets in a group (e.g., `"bullets"`).

   `enemy.gd` only responds to physics-body overlap (`body_entered`). Bullets will likely also be `Area2D`s, so `area_entered` handling (or making bullets `RigidBody2D`/`CharacterBody2D`) is required.

5. **Collision layers/masks are default-only.**  
   Both enemy and player rely on `collision_layer = 1` / `collision_mask = 1`. This is workable but fragile; a dedicated enemy layer/mask would make interaction more explicit.

6. **Enemy manages score itself.**  
   `GameLoop` expects to handle score addition on enemy death, but `enemy.gd` already calls `GameManager.add_score()`. Integration must decide whether `GameLoop` or `EnemySystem` owns scoring. Currently `EnemySystem` does.

7. **Enemy has no spawn behavior or spawn timer.**  
   `enemy.gd` only handles movement and collision. The 2-second random-x spawn logic must live in `GameLoop` (`game.gd`).

8. **No screen-wrap / bounds behavior for enemies beyond bottom despawn.**  
   Enemies only despawn below the viewport; no other cleanup is needed.

## Project Overview
A Godot game project structured around **seven persistent runtime subsystems** attached as children of a single root scene (likely `res://main.tscn` or the project’s main scene). Rather than using traditional Autoloads, the architecture relies on a **node-composition / manager-tree pattern**: `Player`, `Enemies`, `GameControl`, `Audio`, `UI`, `VFX`, and `ProjectDocs` are long-lived sibling nodes that communicate through signals and direct node references.

## Dependencies & Signal Flow
- **GameControl** is the central coordinator: most other modules (`UI`, `Audio`, `Enemies`, `VFX`) connect to its signals (`game_started`, `game_over`, `score_changed`).
- **Enemies** → **Player**: enemy attacks emit `damage_player` or directly call player health functions.
- **Player** → **UI / Audio / VFX**: player death (`died`) and health changes (`health_changed`) drive UI updates, death SFX, and screen-shake/respawn effects.
- **Enemies** → **Audio / VFX / UI**: `enemy_died` triggers score updates, explosion effects, and death sounds.
- **Audio** and **VFX** are largely reactive: they subscribe to signals from `Player`, `Enemies`, and `GameControl` rather than driving logic themselves.
- **ProjectDocs** appears isolated from the gameplay signal graph; if used at runtime, it may only be accessed by UI for help text.

## Issues Found
- **Unusual runtime node**: `ProjectDocs` is listed as a persistent runtime child node. Documentation usually belongs in `res://docs/` or an editor-only plugin, not in the active scene tree.
- **Tight coupling risk**: With all managers as sibling nodes under one root, modules may rely on hard-coded node paths (`get_node("../UI")`) instead of an event bus or Autoload, making refactoring fragile.
- **Lifecycle ordering**: Godot does not guarantee sibling `_ready()` order. If `Enemies` tries to connect to `GameControl` before `GameControl` is ready, signals may be missed unless explicit initialization is handled.
- **Missing event bus**: There is no visible dedicated `Events` Autoload; cross-cutting concerns (e.g., `enemy_died` triggering Audio, VFX, UI, and score) require each manager to connect individually, increasing maintenance overhead.
- **No clear main entry point**: The root scene and startup sequence are not specified; a central `Main`/`Game` scene should explicitly instantiate/own these seven subsystems to clarify load order and ownership.

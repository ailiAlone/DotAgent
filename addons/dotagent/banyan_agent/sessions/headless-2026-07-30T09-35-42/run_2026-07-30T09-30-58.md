### Summary

# Player Subsystem Analysis Summary

## Domain Responsibilities
The Player subsystem owns the playable ship: movement, primary/secondary shooting, two overlapping shield systems, dodge roll, powerup handling, weapon upgrade progression, hit/death logic, and visual self-drawing. It lives under `res://scripts/player.gd` (root `Area2D` in `res://scenes/player.tscn`) with a single `CollisionShape2D` (40×50 rect). Auxiliary files:
- `player_trail.gd/.tscn` — custom-drawn engine trail behind the ship.
- `shield_system.gd` — energy-based toggleable shield resource (autoload-style, instantiated as child).
- `shield_effect.gd/.tscn` — pulsing visual ring that tracks the player when energy shield is active.

## Public Interface

### Exported / Important Variables
- `@export var speed = 420.0`
- `@export var max_hp = 5`
- `var hp = 3`
- `var weapon_level: int` (0–3, setter emits `weapon_level_changed`)
- `var weapon_type: int` (PISTOL=0, SPREAD=1, LASER=2, setter emits `weapon_type_changed`)
- `var weapon_xp: int`, `var weapon_xp_next: int = 500`
- `var shield: bool`, `var shield_timer: float` (timed-shield powerup)
- `var rapid_fire_timer: float`
- `var invuln_timer: float`
- `var dodge_cooldown`, `dodge_duration`, `dodge_dir`
- `const DODGE_DURATION = 0.4`, `const DODGE_COOLDOWN = 1.5`

### Signals Emitted
- `died`
- `shoot(bullet_path, position, direction, extra)` — primary fire
- `shoot_spread(bullet_path, position, direction, extra)` — secondary spread fire
- `hit`
- `powerup_collected(type)`
- `weapon_level_changed(level)`
- `weapon_type_changed(weapon_type)`

### Key Methods
- `fire()` / `fire_spread()` — trigger attacks, fetch stats from `WeaponSystem`, emit `shoot`/`shoot_spread`.
- `take_damage(dmg = 1)` — honors `invuln_timer`, consumes timed `shield` first, otherwise reduces `hp`, emits `hit`, calls `die()` at 0 HP.
- `heal(amount)`
- `apply_powerup(type)` — 0 heal, 1 rapid fire, 2 shield, 3 bomb, 4 score x2, 5 weapon upgrade.
- `upgrade_weapon()` — increments level up to 3, then cycles weapon type.
- `add_weapon_xp(points)`
- `reset()` — called by `game.gd` on respawn.
- `_explode_all_enemies()`
- `_weapon_data()` / `_spread_weapon_data()` — query `WeaponSystem` autoload.

## Dependencies & Callers
- `WeaponSystem` autoload (`res://scripts/weapon_system.gd`) — provides per-type/level stats (`damage`, `fire_rate`, `bullet_count`, `bullet_speed`, `spread`, `color`).
- `GameManager` autoload — score, lives, multiplier (via static `_gm()`).
- `AudioManager` autoload — SFX `shoot`, `powerup`, `explode` (via static `_am()`).
- `Game` scene (`res://scripts/game.gd`) — wires player signals:
  - `shoot` → `_on_player_shoot`
  - `shoot_spread` → `_on_player_shoot_spread`
  - `hit` → `_on_player_hit`
  - `died` → `_on_player_died`
  Also handles collisions: `player.overlaps_area(enemy)` and enemy bullets call `player.take_damage()`.
- `HUD` (`res://scripts/hud.gd`) — `attach_player(player)` connects `powerup_collected`, `weapon_level_changed`, `weapon_type_changed` and reads `hp`, `max_hp`, `rapid_fire_timer`, `shield`.
- `ShopSystem` / `CraftingSystem` autoloads — locate player via `Game/Player`, call `heal`, `upgrade_weapon`, `_explode_all_enemies`, mutate `shield`/`shield_timer`/`rapid_fire_timer`, and increase `max_hp`.

## Issues / Concerns Found
1. **Two shield systems coexist and interact inconsistently**:
   - Powerups/shop/crafting use a simple timed `shield` bool.
   - Input action `shield` uses `ShieldSystem` with energy drain/recharge and separate `shield_effect` visual.
   - They are not integrated; energy shield does not replace timed shield or vice versa.
2. **`take_damage` return values are misleading**:
   - Returns `false` only when `invuln_timer > 0`.
   - Returns `true` when shield absorbs the hit and also after `die()` is called. A dead player returning `true` is semantically odd.
3. **`ShieldSystem` emits `shield_changed` every frame** while active or recharging, causing unnecessary signal traffic.
4. **Secondary spread fire hardcodes type 1 / level 1** (`_spread_weapon_data()`) regardless of the player’s current weapon.
5. **Input registration in `_ready`** adds/removes key events at runtime; this can conflict with project input settings and may not persist reliably.
6. **Player scene** only contains a collision shape; all visuals are drawn in `_draw()`, making hit-box vs. visual alignment hard to verify.
7. **`dodge_dir = input if input.length() > 0 else Vector2.UP`** means pressing dodge while stationary still rolls upward.
8. **Potential signal disconnect leaks**: `player.gd` does not disconnect `ShieldSystem.shield_depleted` or dodge state on exit tree.

## 子系统职责

### 1. Enemy（普通敌人）
- 根节点：`Area2D`，脚本 `enemy.gd`
- 碰撞体：场景内有一个 `CollisionShape2D`，使用 `RectangleShape2D(40x35)`
- 6 种敌人类型：`SCOUT, FIGHTER, TANK, BOMBER, SWEEPER, CARRIER`
- 每种类型拥有独立的 HP、速度、分数、开火频率、颜色和运动模式
- 10% 概率成为精英敌人：2x HP、3x 分数、1.5x 速度、更快射击、金色外观
- `CARRIER` 发射时会额外生成 `SCOUT` 小兵，死亡时还会释放 2-3 只 `SCOUT`
- `SWEEPER` 从屏幕左右两侧水平扫过
- 公共信号：`killed(score_value, position)`、`damaged(hp)`
- 公共方法：`take_damage(dmg=1)`、`set_projectile_container(container)`

### 2. Boss
- 根节点：`Area2D`，脚本 `boss.gd`
- 血量：120 HP，固定位置 `y=140`
- 3 阶段：
  - Phase 0：满血，单发追踪玩家
  - Phase 1：HP ≤ 66%，3 发散射
  - Phase 2：HP ≤ 33%，16 向环形弹幕
- 入场动画：从屏幕上方缓缓下降到固定位置
- 左右摆动 + 轻微上下浮动
- 公共信号：`killed(score_value, position)`、`damaged(hp)`
- 公共方法：`take_damage(dmg=1)`、`set_projectile_container(container)`
- **⚠ 已知问题：Boss 场景的 `CollisionShape2D` 未指定 shape，碰撞不会生效**

### 3. Asteroid（小行星）
- 根节点：`Area2D`，脚本 `asteroid.gd`
- 碰撞体：圆形 `CircleShape2D(radius=25)`
- 程序化生成随机多边形，HP 随机 2-5，大小 0.7-1.5
- 死亡时分裂为 3 个碎片小行星
- 使用 `area_entered` 信号处理碰撞，与 Enemy/Boss 不同
- 与子弹或玩家碰撞后掉落 crafting 材料

### 4. Enemy Bullet
- 场景：`enemy_bullet.tscn`
- 使用脚本：`bullet.gd`（通用子弹脚本，非专用 enemy_bullet.gd）
- 碰撞体：`RectangleShape2D(8x32)`
- 由 Enemy/Boss 实例化并设置 `is_enemy=true` 和向下速度
- 视觉： trail + glow 光效，依赖场景中是否存在对应节点

## 依赖与调用关系

- **生成控制器**：`game.gd`
  - 普通敌人：`game._spawn_enemy()` → `_make_enemy()` → `enemy.tscn`
  - Boss：`game._spawn_boss()` → `boss.tscn`
  - 小行星：`game._spawn_asteroid()` → `asteroid.tscn`
  - 所有敌人都通过 `set_projectile_container(bullets)` 传入子弹容器
- **碰撞检测**：由 `game._collisions_check()` 统一处理
  - 敌人与玩家重叠：玩家受伤 2，敌人受到 99 伤害
  - 玩家子弹与敌人重叠：调用 `enemy.take_damage(b.damage)`
  - 敌方子弹与玩家重叠：玩家受伤 1
- **全局系统**：
  - `GameManager`：分数、生命、高分
  - `AudioManager`：播放 shoot/explode/warning 音效
  - `CraftingSystem`：敌人/小行星/Boss 死亡掉落材料
- **信号**：
  - `enemy.killed` / `boss.killed` → `game._on_enemy_killed()` / `game._on_boss_killed()`
  - `enemy.damaged` / `boss.damaged` → `game._on_boss_damaged()`，Enemy damaged 未连接

## 发现的问题

1. **Boss 碰撞体缺失**：`boss.tscn` 的 `CollisionShape2D` 没有 `shape` 属性，导致 Boss 无法被子弹击中。
2. **Enemy 的 damaged 信号未连接**：在 `game.gd` 中只连接了 `killed`，没有连接 `damaged`，因此受伤时的震屏/特效只在 Boss 身上有。
3. **碰撞机制不一致**：Asteroid 使用 `area_entered` 信号，而 Enemy/Boss 依赖 `game._collisions_check()` 的 `overlaps_area()` 轮询，两套机制并存。
4. **Enemy 子弹类型不统一**：Enemy/Boss 使用 `bullet.gd` 脚本，但项目还有 `bullet_pooled.gd` 池化版本，目前未在敌人子弹中使用。
5. **`_on_boss_damaged` 震屏较弱**：Boss 受伤仅 0.04 秒/振幅 2，反馈不明显。

# GameMaster Domain Summary

## Domain Responsibility

This domain owns the high-level game flow and scene management:
- **Bootstrap & singleton setup** (`main.gd` / `main.tscn`)
- **Global game state & leaderboard** (`game_manager.gd`)
- **Core gameplay scene & loop** (`game.gd` / `game.tscn`)
- **Menu / Pause / GameOver / Leaderboard UIs**

## Key Mechanisms

### 1. Bootstrap (`res://scripts/main.gd`, `res://scenes/main.tscn`)
- `Main` is the root runtime scene.
- On `_ready()` it ensures two singletons are attached directly to `get_tree().root`:
  - `GameManager`
  - `AudioManager`
- It ensures input actions exist: `alt_shoot`, `dodge`, `shop`, `crafting`.
- Finally it instantiates `menu.tscn` as its child.

### 2. Global State (`res://scripts/game_manager.gd`)
- Autoload-style singleton with `process_mode = PROCESS_MODE_ALWAYS`.
- Tracks `score`, `high_score`, `lives`, `combo`, `score_multiplier`.
- Emits signals: `score_changed`, `high_score_changed`, `lives_changed`.
- Maintains a 10-entry leaderboard persisted to `user://leaderboard.save`.
- `high_score` is derived from the top leaderboard entry.

### 3. Gameplay Loop (`res://scripts/game.gd`, `res://scenes/game.tscn`)
- Root node is `Node2D`.
- Contains player, bullets, enemies, effects, powerups, asteroids, timers, camera, star field, and a unified `UI_Layer` CanvasLayer holding HUD and PauseMenu.
- Manages waves (`wave`), spawn timers, difficulty, hitstop, pause, game-over, and progress saving via `SaveManager`.
- Uses static helper methods `_gm()`, `_am()`, `_sm()` to access singletons.

### 4. Scene Transition Pattern
- All major scenes (Menu → Game → GameOver → Menu, etc.) are instantiated as children of `Main` (falling back to `root`).
- The outgoing scene calls `queue_free()` after adding the new scene.
- No `SceneTree.change_scene_to_file()` is used.

### 5. Pause Flow
- `Game._toggle_pause()` toggles `get_tree().paused` and `pause_menu.visible`.
- `PauseMenu` uses `PROCESS_MODE_ALWAYS` and listens for ESC in `_unhandled_input` to resume.
- Pause menu supports Resume / Save / Load / Restart / Menu.

### 6. GameOver & Leaderboard
- `GameOver` shows final score, best score, reached wave, and a NEW RECORD indicator.
- `Leaderboard` dynamically builds rows from `GameManager.get_leaderboard()` and emits `back_pressed`.

## 音频子系统分析总结

### 1. 核心机制与职责
- **AudioManager (`res://scripts/audio_manager.gd`)** 是一个运行时单例，由 `main.gd` 在 `/root` 下自动创建（`process_mode = ALWAYS`），保证切场景/暂停时继续存在。
- **职责**：

  - 播放程序化生成的背景音乐（Music）：单个循环播放的 `AudioStreamPlayer`。
  - 维护 `_sfx_cache` 与 `_music_cache`，避免重复生成 WAV 数据。
- **音频总线**：所有 SFX 与 Music 播放器都挂在 **Master** 总线上；音乐播放器默认 `volume_db = -10`。

### 2. 公共接口

| 方法 | 说明 |
|------|------|

### 4. 音量控制与静音
- **实际控制由 `SettingsManager` 负责**：读取/保存 `user://settings.cfg`，提供 `master_volume`、`sfx_volume`、`music_volume` 三个导出变量。
- `SettingsManager.apply_audio_buses()` 通过 `AudioServer.set_bus_volume_db()` 设置 `Master`、`SFX`、`Music` 三条总线。
- **关键问题**：`AudioManager` 的所有播放器都显式设置为 `bus = "Master"`，因此 `SFX` 和 `Music` 音量滑块对 AudioManager 输出**无效**。玩家调整 SFX/Music 音量时，只会影响其他使用这些总线的代码，而当前项目中 AudioManager 独占 Master。

### 5. 发现的问题与隐患
1. **总线隔离失效**：SFX 与 Music 未分别走 `SFX` / `Music` 总线，导致 `SettingsManager` 的 sfx/music 音量设置不生效。
2. **缺少显式静音 API**：若 UI 需要一键静音，需要额外逻辑或修改 AudioManager。
3. **音乐与 SFX 共用 Master**：无法独立调节音乐与音效。
4. **暂停行为**：`AudioManager` 为 `PROCESS_MODE_ALWAYS`，暂停时音乐继续播放；若希望暂停菜单静音音乐，需要额外处理。
5. **无 default_bus_layout 检查**：SettingsManager 引用 `SFX` 和 `Music` 总线，若项目未配置这些总线，`get_bus_index` 会返回 -1 并被静默跳过，导致音量设置完全无效且无警告。

### 公共接口

- **`ParticleManager`（class_name）**
  - `static spawn_explosion(parent: Node, world_position: Vector2, size=1.0, color=Color(1.0,0.6,0.2))`
  - `static spawn_smoke(parent, world_position, size=1.0, color=Color(0.5,0.5,0.5))`
  - 内部容器定位：优先挂在 root 下名为 `Effects` 的 `Node2D` 节点。

  - `spark(color: Color, intensity: float = 1.0)`：产生火花粒子。

- **`screen_flash.gd`**
  - `flash(intensity: float = 0.5)`：触发全屏红闪。

- `ParticleManager` 依赖所有特效场景（`explosion.tscn` 等）。

### 发现的问题

1. **护盾场景脚本丢失**  
   `res://scenes/shield_effect.tscn` 当前只是一个空的 `Node2D`（名为 `ShieldEffect`），**没有挂载 `res://scripts/shield_effect.gd`**。这是明确的 bug：护盾特效不会被绘制，也不会跟随父节点。

2. **命中火花必须二次调用**  
   `hit_spark.tscn` 实例化后不会自动播放，必须手动调用 `spark()`。如果调用方不知道这一点，会导致特效不显示。

3. **Smoke 未独立实现**  
   `spawn_smoke` 只是复用了爆炸场景，视觉上不够像烟。

4. **PlayerTrail 未使用 `top_level=true`**  
   虽然当前靠局部坐标绘制，但如果父节点发生旋转/缩放，尾迹点会跟随形变。建议根据实际使用场景确认是否需要世界坐标。

5. **未使用对象池**  
   所有特效都是 `instantiate()` → `queue_free()`，高频调用时可能产生 GC 压力。不过当前项目规模较小，暂不严重。

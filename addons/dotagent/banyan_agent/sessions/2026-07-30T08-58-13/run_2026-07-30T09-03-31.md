## 音频系统最终分析（无文件改动）

### 分析范围
- 核心文件：`res://scripts/audio_manager.gd`
- 关联文件：`settings_manager.gd` 以及多个调用方的部分读取，用于确认依赖关系。

### 1. 系统定位
`AudioManager` 是一个 Godot Autoload 全局单例，继承自 `Node`。它完全通过运行时 PCM 合成生成所有音效与音乐，**不依赖任何外部音频资源文件**。

### 2. SFX 合成机制
- 采样率：22050 Hz
- 格式：16-bit mono PCM
- 缓存：`_sfx_cache` 按 `type` 缓存生成的 `AudioStreamWAV`
- 播放池：16 个 `AudioStreamPlayer` 实例，优先使用空闲播放器，全部占满时停止最老的一个复用。

| 音效类型 | 时长 | 合成算法 |
|----------|------|----------|
| `shoot` | 0.09s | 1400→220Hz 降频正弦 + 快速衰减 |
| `hit` | 0.20s | 降频正弦 + 噪声包络 |
| `explode` | 0.50s | 白噪声 + 低频震荡 |
| `powerup` | 0.45s | 440→1240Hz 升频正弦 |
| `click` | 0.04s | 1600Hz 极短衰减 |
| `damage` | 0.25s | 噪声包络 |
| `gameover` | 1.20s | 440→70Hz 长降调 |
| `wave` | 0.60s | 660+990Hz 双音正弦 |
| `warning` | 0.50s | 0.18s 周期 burst 880Hz |

### 3. BGM 合成机制
仅支持 `game` 和 `menu` 两轨：
- `game`：BPM 130，16 beats，旋律偏紧张
- `menu`：BPM 80，更舒缓
- 使用固定 `notes` 和 `bass_notes` 数组 + 包络 + 随机鼓点生成
- 循环模式：`AudioStreamWAV.LOOP_FORWARD`

### 4. 调用接口
- `play_sfx(type)`：播放音效，内部随机 `volume_db(-3, 0)` 和 `pitch_scale(0.92, 1.08)`
- `play_music(track)`：播放音乐，切换时停止当前音乐
- `stop_music()`：停止音乐

### 5. 导出的音量控制接口
`AudioManager` 本身**没有导出任何音量控制参数**。实际音量控制由 `SettingsManager` 通过 `AudioServer.set_bus_volume_db` 设置 `Master` / `SFX` / `Music` bus 实现。但当前所有 AudioManager 的播放器都挂在 `Master` bus 上，因此 `SFX` 和 `Music` bus 的独立滑块目前不生效。

### 6. 依赖关系
- `AudioManager` 自身不暴露任何信号。

## 2. 公共接口

### 2.1 HUD (`hud.gd`)
- `attach_player(p)`：绑定玩家实例，连接 `powerup_collected`、`weapon_level_changed`、`weapon_type_changed`。

- 订阅 `GameManager.score_changed`、`high_score_changed`、`lives_changed`。
- 依赖 `WeaponSystem.weapon_type_name(type)` 显示武器名。

### 2.2 主菜单 (`menu.gd`)
- `_on_start()` / `_on_quit()`：开始游戏或退出。
- 通过 `_get_scene_holder()` 找 `Main` 节点作为新场景父节点。

### 2.3 暂停菜单 (`pause_menu.gd`)

### 2.4 游戏结束 (`game_over.gd`)
- 字段：`final_score`、`wave_reached`（外部在实例化后设置）。

### 2.5 排行榜 (`leaderboard.gd`)
- `back_pressed` 信号；`_refresh_list()` 读取 `GameManager.get_leaderboard()`。

### 2.7 制作 UI (`crafting_ui.gd`)

## 3. 数据流

### 3.1 游戏流程数据流
```
主菜单 (menu.tscn) 
  → 点击 START 
  → 实例化 game.tscn 并加入 Main
  → Game 内部实例化 HUD
       ↓
    HUD 监听 GameManager 分数/生命/最高分变化
    HUD 通过 attach_player() 监听玩家武器、HP、道具状态
       ↓
    玩家死亡/游戏结束 
  → Game 实例化 game_over.tscn，设置 final_score / wave_reached
       ↓
    游戏结束界面：重试 → game.tscn；菜单 → menu.tscn
```

### 3.2 暂停数据流
```
Game._toggle_pause() 设置 get_tree().paused
  ↓
PauseMenu process_mode = PROCESS_MODE_ALWAYS，保持响应
  ↓
继续 → 调用 game._toggle_pause()
保存 → 组装 {score, high_score, wave, lives} → SaveManager.save_game()
加载 → SaveManager.load_save() → 校验 → game.apply_save_data()
重玩/菜单 → 重置 paused=false → 切换场景
```

### 3.3 商店/制作数据流
```
按键打开 ShopUI / CraftingUI (process_mode = ALWAYS)
  ↓
open() → 动态构建 Button 列表 → 显示分数/材料
  ↓
玩家点击 → 调用 ShopSystem.purchase() / CraftingSystem.craft()
  ↓
成功/失败信号 → 更新分数/库存标签与按钮禁用状态
```

### 3.4 存档数据流
```
SaveManager 持久化：
  user://save.json         → score/high_score/wave/lives/version/timestamp
  user://crafting.save     → 制作材料库存

SettingsManager 持久化：
  user://settings.cfg      → audio.master/sfx/music + game.difficulty
```

## 4. 关键发现

1. **UI 依赖模式统一**：所有 UI 脚本都通过 `Engine.get_main_loop().root.get_node_or_null("XxxManager")` 获取 autoload，而不是在 `_ready` 中直接引用节点路径。
2. **暂停兼容性**：`pause_menu.gd`、`shop_ui.gd`、`crafting_ui.gd` 都设置了 `process_mode = Node.PROCESS_MODE_ALWAYS`，保证暂停时仍可交互。
3. **排行榜数据来自 GameManager**：`leaderboard.gd` 不直接操作文件，而是调用 `_gm().get_leaderboard()`。
4. **设置场景不完整**：`settings_menu.tscn` 仅有 Label 占位，缺少 Slider、CheckBox 等控件，也没有挂载脚本，因此设置菜单无法实际使用。
5. **`save_manager_new.gd` 是临时残留**：文件内容只有 `# Temporary file - can be deleted.`，应删除。
6. **SettingsManager 的信号无人监听**：`master_volume_changed` 等信号被声明并发射，但当前没有任何脚本连接它们。
7. **保存/加载范围有限**：暂停菜单保存只存 `score/high_score/wave/lives`，未保存玩家位置、敌人、子弹、材料库存等完整状态。

## 5. 潜在问题

| 问题 | 影响 | 建议 |
|------|------|------|
| `settings_menu.tscn` 无交互控件与脚本 | 设置菜单无法使用 | 补充 Slider（音量）、OptionButton（难度）、返回按钮，并挂载脚本调用 SettingsManager |
| `save_manager_new.gd` 残留 | 污染项目 | 删除 |
| 暂停存档不完整 | 加载后可能丢失玩家状态与敌人布局 | 扩展 `save_game` / `apply_save_data` 保存完整游戏状态，或明确仅支持"波次/分数续关" |
| 多个 UI 脚本重复实现 `_get_scene_holder()` | 维护成本 | 可提取到共享工具类或基类 |
| HUD 的 `combo_label` 逻辑覆盖自身 | 当 `score_multiplier > 1` 时覆盖 combo 显示，可能导致 combo 值丢失 | 拆分 combo 与 multiplier 显示 |
| `SettingsManager` 信号未连接 | 当前虽然可用，但 UI 无法响应设置变化 | 添加 Slider 连接这些信号 |
| 排行榜 `leaderboard.gd` 的 `_make_label` 返回 Label 但没有设置字体颜色主题 | 不影响功能，但样式不一致 | 可统一主题 |
| 部分场景根节点 `anchors_preset = 0` | 在动态分辨率下可能不铺满屏幕 | 检查并设置 anchors_preset = 15 |
